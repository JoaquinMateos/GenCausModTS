# Rerun plan after the 2026-10-31 full benchmark

**Run analysed:** `outputs/` and `outputs_shared/` from the ten-seed run on the
2080 host (code revision `2d5deb9`, errors logged 2026-10-27 and 2026-10-31).
This document supersedes the status claims in
`docs/failure_analysis_and_rerun_plan.md` (see §2.4). It has three parts: what
failed and why (§1–2), which results are reusable and what must be rerun (§3),
and the protocol for executing the reruns and analysing them (§4–5).

> **Update (local MPS execution).** The reruns and the analysis have been carried
> out locally on an Apple M4 (MPS). Two additional defects were found and fixed

### 1.1 Root causes

**RC1 — the Lotka pool on the host predates the generator fix, and the generator
never replaced it.** `physics.py` was corrected on 20 Oct (positive initial
states, state clamping), and the local pools were regenerated that evening; the
local Lotka pools are finite and train normally (§3.2). The host's pool is
non-finite (inferred from the failure; the host itself has not been inspected). `run_2080.sh` calls `generate_synthetic_data.py` without
`--force`, and the generator skipped every existing pool, so the stale pool was
never replaced. The 2026-10-16 doc recorded this same failure (R2) and asked for
a regeneration step; that step did not reach the host.

*Fix:* the generator now skips an existing pool only if it is finite and
regenerates the rest with a warning (`scripts/generate_synthetic_data.py`,
`_existing_is_usable`). `run_2080.sh` runs `verify_outputs.py --pools-only` after
generation and stops if any pool is non-finite. `_load_pool` also rejects a
stored non-finite pool with the regeneration command.

**RC2 — divergence was silent.** `SimpleTrainer` skipped every non-finite step and
continued (225,750 skipped steps in the Lotka log). Early stopping then fired on
an infinite validation loss, and `run_crl_shared.py` stored the NaN metrics as a
normal result. Nothing failed.

*Fix:* the trainer raises `TrainingDivergedError` after more than 200 consecutive
non-finite steps, or when validation was never finite. `run_crl_shared.py` records
a diverged run as a failure (not stored), logs it, and exits 1. A run with no
finite metric is refused.

**RC3 — table completeness and crashes.** `write_crl_summary` indexed MCC directly
and counted rows as complete. It now requires a finite MCC, and the caption names
any pending block. Runners wrap their loops, so a crash marks the progress file
`failed` with `errors ≥ 1` (`ProgressTracker.crash`). Previously both NEWS and
Oregon exited with `errors: 0`.

**RC4 — News has 50 realisations.** The archive (`data/static/news.zip`) contains
`topic_doc_mean_n5000_k3477_seed_{1..50}`, two files each. The protocol said
100. `news_replications_available` counts the realisations; `NewsLoader` and
`run_ctee_static.py` refuse an index past the available count, and the
orchestrator caps News at the available count with a warning. The NEWS config
of the failed run records `replications: 100` and must not be reused.
*Paper impact:* Appendix I (`latex/appendix/I_audit.tex`, line 194) states
`--replications 100` for News; it must say 50.

**RC5 — the Oregon archive is manual.** The Dataverse requires a browser download.
The orchestrator now skips a real cohort whose input file is missing, with a
warning (`REAL_COHORT_INPUTS` in `scripts/run_full_benchmark.py`), instead of
starting a step that will fail. The file exists locally
(`data/real/dataverse_files/Oregon/oregon_puf.zip`, 9.4 MB) and must be copied to
the host.

**RC6 — progress accounting.** The static runners credit the two deterministic
baselines per replication in `done`, but `total` counts only the four learned
methods. The total now includes the baselines. The footer is a sum of per-step
counters, so this is the only correction needed. The 16 Oct doc's explanation
(restart artefact) does not cover this run.

### 1.2 Why the 16 Oct doc was wrong about Lotka

That doc says R2 was fixed and the Lotka block was rerun successfully. This run
shows the same divergence on the same host. Either the successful rerun used
different pools or the regeneration step was skipped (RC1 suggests the latter).
Its "completed" claims for the Lotka block cannot be verified and should not be
cited.

## 4. Execution on the 2080 host

Everything below runs in `~/gcmts` on the host. Commit and push this change set
first; the host pulls it.

### 4.0 Sync and inputs

```bash
cd ~/gcmts && git pull
# Copy the manually downloaded archive from the Mac (run on the Mac):
#   scp data/real/dataverse_files/Oregon/oregon_puf.zip <host>:~/gcmts/data/real/dataverse_files/Oregon/
```

The fingerprint in every `<stem>_config.json` includes the code revision, so the
old results will refuse to resume under the new revision. This is intended. The
reruns below use fresh stems or archive the old files first.

### 4.1 Pool gate (must pass before anything else)

```bash
uv run --no-sync python scripts/generate_synthetic_data.py --seeds 10 \
    --suites lotka_volterra duffing fitzhugh_nagumo van_der_pol pendulum mountain_car
uv run --no-sync python scripts/verify_outputs.py --pools-only
```

The first command regenerates only non-finite pools and logs each one. The second
must exit 0. If it does not, stop and report which pool failed.

### 4.2 Equivalence check on CUDA

The CPU check shows that the code change leaves healthy runs unchanged. The
production runs used CUDA, so repeat the check on one healthy suite:

```bash
uv run --no-sync python scripts/run_crl_shared.py --device cuda --suite duffing \
    --seeds 1 --epochs-scale 1.0 --data-source pool --dataset-dir data/synthetic \
    --scheduler adaptive --early-stopping-patience 300 --ema-decay 0.99 \
    --kl-warmup-epochs 50 --no-baselines --out-dir outputs_eq
uv run --no-sync python - <<'PY'
import json
new = {r["method"]: r for r in json.load(open("outputs_eq/crl_shared_duffing.json"))}
old = {r["method"]: r for r in json.load(open("outputs_shared/crl_shared_duffing.json"))
       if r["seed"] == 0}
worst = max(abs(new[m]["mcc"] - old[m]["mcc"]) for m in old)
print("max |delta MCC| over methods, seed 0:", round(worst, 4))
PY
```

Accept if the largest difference is at most 0.01 MCC (GPU reduction order is the
only expected source of drift). If it is larger, do not reuse the other blocks;
use §4.5 (full rerun). The tolerance is a judgement made before the check, not
after seeing it.

## 5. Analysis plan

The rerun removes known failures. It does not show that the completed results
agree with the original papers. The analysis below is a separate step, applied
after §4.6, and it can require further reruns.

### 5.1 Acceptance per block (automatic)

`verify_outputs.py` checks, per stem: all methods present; full seed or replication
count (from the stored config); no run without a finite metric; every progress
file finished with `errors = 0`; and every all-NaN metric classified as
`EXPECTED` (by design: baselines have no training loss, persistence has no
reconstruction, real cohorts have no counterfactual truth, CEGEN has no latent
MCC, the oracle has no `mig`/`cds`) or `REVIEW`.

### 5.2 Agreement with the original papers (manual, per method)

For each method and each benchmark it is compared on, record in a table:

1. The original paper's setting (generator, dimensionality, sample size, metric
   definition) from `papers/markdown/`.
2. Whether our benchmark reproduces that setting. If not, the comparison is
   qualitative only: a ranking or a sign, never a number transferred across
   generators.
3. Verdict: *consistent*, *inconsistent*, or *not testable*.

Only verdicts of *inconsistent* on a reproduced setting trigger a rerun.

### 5.3 Known discrepancies to resolve before any claim is written

These come from the current outputs. Each is a hypothesis to test, not a finding.

- **Neural CTEE estimators on IHDP are far worse than the published ones.** Ridge
  T-learner √PEHE is 2.40 (IHDP, 100 realisations), close to OLS/LR-2 in Shalit et
  al. (2017, IHDP table: 2.4 in-sample, 2.5 out-of-sample). CaTSG, CEPAE, CRN and
  GANITE are 4.0–5.1 on the same benchmark, 1.6–2.7 worse than ridge. In the
  in-sample block of the same table, TARNet, CFRNet-MMD and CFRNet-Wass report
  0.71–0.88; the out-of-sample neural values are not in the excerpt read, so
  compare against them before quoting. Our benchmark is out-of-sample. The
  published ordering (neural better than OLS) is reversed here. Test: check the outcome scaling
  (IHDP outcomes are rescaled by `rescale_outcome`), the number of epochs, and
  early stopping in `run_ctee_static.py`. A CRN collapse to a near-zero effect
  (the 16 Oct summary) would show as a near-constant prediction; check the spread
  of `tau_hat`. Rerun CTEE static only if a defect is confirmed.
- **LaLonde neural ATE errors ~1,500 versus 213 for ridge.** The real cohort loader
  passes raw `re78` dollar earnings. Hypothesis: neural estimators are not
  standardising the outcome. Test: compare the outcome scale each estimator sees.
  If confirmed, rerun the LaLonde cohort (1 replication, minutes).
- **Twins: PEHE 0.32 ± 0.01 for every method.** This is not a loader bug: the
  replications differ only in the treatment draw and the split, and the potential
  outcomes are fixed. Report the spread as a sampling artefact, and add a
  constant-ATE predictor as a PEHE floor on every panel. A learner that does not
  beat the floor has learned nothing about heterogeneity.
- **Persistence and AR(1) beat every learner at one step on 10 of 11 panels.**
  Check that learners receive the same context window and horizon as the
  persistence baseline before concluding that the utility claim holds.
- **The 18-problem grid has no significant MCC ranking** (Friedman p = 0.128),
  while one-step forecasting separates the methods (p ≈ 10⁻¹⁵). Confirm that the
  forecasting ranking is not driven by one suite before stating it.
- **Real-panel rows carry no seed.** Count per case is verified, but per-seed
  pairing is not. If any real-panel claim depends on pairing, rerun
  `real_benchmarks` (≈ 55 h) with the seed recorded.
